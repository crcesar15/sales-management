# OpenCode Setup

This repository supports OpenCode only. Its application-specific rules, agents, and MCP configuration are committed; downloaded skills and binaries are not.

## New Device Setup

```bash
composer install
npm ci
npm run ai:setup
npm run ai:doctor
```

OpenCode V2 reloads configuration and skills automatically. Reload the client if its command picker is stale; do not restart a healthy server just to apply configuration.

`npm run ai:setup` restores the project skills pinned in `skills-lock.json`, installs the pinned Impeccable package, generates Laravel Boost skills for the installed PHP packages, and explicitly generates the OpenCode integration with the pinned OpenSpec CLI and core profile. It works on fresh checkouts without existing generated files and preserves `openspec/config.yaml`. It does not update dependencies, change global OpenCode settings, or require provider credentials. OpenSpec's global delivery setting should remain `both` (the default) to generate both skills and slash commands.

Sign in to providers separately on each device through OpenCode. Desktop installations may have a different `PATH` than a terminal session; launch `npm run ai:doctor` from the same environment if Laravel Boost is unavailable.

## Maintaining Skills

Do not edit an installed third-party skill in place. Update a dependency deliberately, review the change, and commit the changed lockfile. `npm run ai:setup` always restores the committed lock state.

Some `skillPath` values in `skills-lock.json` describe the upstream repository layout and may mention another agent directory. They do not create or enable that agent locally.

Run `npx --no-install skills check` to inspect third-party skill updates. Run `npx --no-install impeccable check` to inspect Impeccable updates. Neither command updates the project automatically.

Project-specific guidance belongs in `AGENTS.md`, `.opencode/rules/`, `.opencode/agent/`, or a tracked project skill under `.opencode/skills/`.

## Product Improvement Workflow

Read `.opencode/rules/product-workflow.md` for task routing, skill selection, discovery interviews, and browser/design safeguards.

- **Kanban:** overall backlog and small improvements. Larger cards reference an OpenSpec change.
- **OpenSpec:** requirements, design, implementation tasks, and verification for substantial or risky changes.
- **Worktree Decisions:** meaningful choices and their reasons; incorporate lasting rules into repository documentation only after review.
- **Context:** read-only context usage diagnostics; category estimates are not exact measurements.
- **Git Graph (MltStephane):** read-only history and commit diffs.
- **Design Studio:** preferred browser provider and targeted visual iteration.
- **Server Browser:** installed, disabled fallback. The host selects one provider per instance; the two extensions can coexist.
- **Skill Bundles:** project-scoped organizational groups, all enabled, with no skill-mode overrides applied.

The extensions are user/instance installations, not npm dependencies of this application. Installing this repository on another device does not install them. Use **Settings → Extensions** to review permissions, enable/disable, and update them.

### OpenSpec

The CLI is pinned to **1.13.1**, the version tested by the board extension. Review board compatibility before upgrading to a new CLI major version.

The extension invokes `openspec` by name, so the CLI must also be available on the OpenChamber service's PATH. This machine has the same version installed globally:

```bash
npm install --global @fission-ai/openspec@1.13.1
openspec config set telemetry.enabled false
```

For repository commands, prefer the pinned dependency:

```bash
npx --no-install openspec list --json
npx --no-install openspec list --specs --json
npx --no-install openspec validate --all --strict --no-interactive
```

Available commands: `/opsx-explore`, `/opsx-propose`, `/opsx-update`, `/opsx-apply`, `/opsx-sync`, and `/opsx-archive`.

No business baseline was fabricated during setup. `openspec/specs/` starts empty. Spec Miner installation and module-by-module discovery are a separate next step. Existing `docs/PRD.md` and phase documentation should be reviewed as evidence, not assumed to match the current application.

### Browser Compatibility

Design Studio was smoke-tested through the agent browser tool on this Linux desktop. Its installed source and compiled service have a local compatibility adjustment:

- Use `/usr/bin/google-chrome` on Linux instead of the macOS application path.
- Supply the current desktop's `:0` display and discover the GNOME Xwayland authority-file path when the host filters those environment variables. No authority-file contents are copied into the project.

These changes are outside the repository, under `~/.config/openchamber/extensions/design-studio/service/{browser.ts,main.js}`. A future extension update may replace them: review the diff, re-check Linux support, and smoke-test after updating. Other display numbers or desktop environments may need different configuration.

Design Studio 0.1.0 does not implement every browser action exposed by the host (for example, `browser.close`). Use its own Stop control to close its window.

Design Mode remains off; no project harness, new design preset, or replacement application was generated. Review the harness before first enabling it and keep existing PrimeVue configuration authoritative.

### Skill Bundles Safety

This machine's bundle definitions live in `~/.config/opencode/skill-bundles.json`. No global OpenCode permissions or downloaded skill files were changed, and no bundle defaults were applied.

The extension requires `~/.config/opencode/opencode.json`; it does not fall back to `opencode.jsonc`. On this machine the original schema-only, valid-JSON `opencode.jsonc` was backed up as `opencode.jsonc.backup-*` and renamed to `opencode.json` with the user's approval. Its contents were preserved and only one active global config file remains. On another device, inspect and back up the existing configuration before making this adjustment; do not create competing active config files.

Some project skills live under `.agents/skills/` and do not appear in the extension's default global discovery. The verified default scan on this machine currently discovers only the global `find-skills` skill. The project's other skills remain available to OpenCode; bundle membership alone does not install or expose a missing skill in this panel. Do not move or edit dependency-managed skills, or expose project-specific skills globally merely to make them visible; preserve `npm run ai:setup` and mandatory skill triggers.
