## Executive Summary

Repair the settings cache for the `file` driver, add eager loads to eliminate N+1 queries in reception and sales orders, extract the claimed-quantities aggregation into `ReceptionOrderService`, and convert service delete guards from generic `Exception` to `InvalidArgumentException` so the narrowed controller catches in Plan 01-05 can handle them. This plan depends on Plan 01-02 because it assumes the FIFO/recalculate contracts are stable.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Settings cache → Storage | `file` driver does not support tags; cache invalidation must be key-based. |
| Service layer → Database | Missing eager loads cause N+1 queries that leak performance behavior. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-03-S1 | Denial of service | `Setting` cache (FIX-18) | mitigate | Replace `Cache::tags()` with key-based `Cache::rememberForever()` + explicit forget. |
| T-01-03-S2 | Information disclosure | `ReceptionOrderService` / `SalesOrderService` (FIX-19/20) | mitigate | Eager load relations so resources do not trigger query cascades. |
| T-01-03-S3 | Tampering | Service delete guards (FIX-14 service side) | mitigate | Throw `InvalidArgumentException` for business-rule guards so controllers catch them consistently. |
</threat_model>
