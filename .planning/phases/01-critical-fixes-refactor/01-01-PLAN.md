## Executive Summary

Repair the existing financial core so later features build on trustworthy services. This plan executes the 22 `FIX-XX` requirements as six ordered waves: (1) FIFO consolidation + stock/core services, (2) cash-register shift state machine + resource serialization, (3) settings cache + eager loads + dead code + sort whitelisting + log rotation, (4) API authorization + mass-assignment + resource return format, (5) frontend tax parity + CSRF fix, and (6) targeted Pest tests + full lint/type-check pass. All locked decisions from `01-CONTEXT.md` (D-01 through D-07) are implemented verbatim; no deferred work from later phases is included.

Available subagents if the executor needs focused help: `@refactoring` for convention alignment of touched files, `@test-writer` for Pest coverage.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser → API (`useApi.ts`) | Untrusted client sends HTTP requests; CSRF token must be handled by Axios, not a raw DOM element. |
| Public API controllers (`routes/api.php`) | Anonymous/token-authenticated requests cross here; authorization and input validation are enforced. |
| Web controllers → Service layer | User input reaches business logic; controllers only catch business-rule exceptions. |
| Service layer → Database | SQL construction and state transitions; raw user input must be whitelisted. |
| Settings cache → Storage | `file` driver does not support tags; cache invalidation must be key-based. |
| Log files → Disk | Unbounded logs can exhaust disk; rotation bounds resource use. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-01 | Tampering | API controllers (FIX-01) | mitigate | Replace `$request->all()` with `$request->validated()` from API Form Requests. |
| T-01-02 | Elevation of privilege | API controllers (FIX-02) | mitigate | Add `$this->authorize(PermissionsEnum::X->value, auth()->user())` per action. |
| T-01-03 | Tampering / Information disclosure | Service `list()` methods (FIX-13) | mitigate | Per-service `SORT_COLUMN_MAP` whitelist + `asc`/`desc` direction validation. |
| T-01-04 | Information disclosure | Web controllers (FIX-14) | mitigate | Catch `InvalidArgumentException` only; other exceptions propagate to the global handler. |
| T-01-05 | Denial of service | `Setting` cache (FIX-18) | mitigate | Replace `Cache::tags()` with key-based `Cache::rememberForever()` + explicit forget. |
| T-01-06 | Denial of service | `config/logging.php` / `storage/logs/browser.log` (FIX-22) | mitigate | Switch default stack to `daily`; bound `browser.log` via a configured daily channel. |
| T-01-07 | Information disclosure | `CashRegisterShiftResource` / `StockTransferResource` (FIX-03/04/05) | mitigate | Use `whenLoaded()` and explicit date/identifier fields; return Resources instead of raw models. |
| T-01-08 | Tampering | `FifoStockDeductionService` / `CashRegisterShiftService` (FIX-11/12) | mitigate | Centralize business rules; throw `InvalidArgumentException` for invalid state. |
</threat_model>
